# Agent tooling decisions

The rules live in `AGENTS.md`, `.cursor/rules/` and the skills; this lists why they exist and what was rejected.

- Skills: `.agents/skills/` (the Agent Skills standard) is the single source; `.cursor/skills` and `.claude/skills` symlink to it and `.claude/commands` to `.cursor/commands`. A Cursor-only location left Claude Code and Codex without skills, and per-tool copies drifted. Windows clones need `core.symlinks`.
- Attribution: no `Co-Authored-By` or "Generated with" lines; `scripts/strip_watermarks.py` strips them (prek, edit hooks, skill `ship`) and `pr-title.yaml` rejects them. Banners add noise; a check-only hook let agents re-add them.
- Delivery: skill `ship` is the only path. `scripts/pr_policy.py` calls a branch routine or review; `scripts/hooks/merge_gate.sh` merges only on a routine marker for `HEAD`; permissions deny force pushes, pushes to `main`, drafts, squash and rebase merges. Security-relevant changes never auto-merge, even as `chore`; Claude answers review threads on its own PR only. It watches CI to green and keeps `main` merged in, because a red or stale PR costs the maintainer a round trip.
- Review: Claude reviews its own diff locally (skill `review`, agent `reviewer`) and never comments on GitHub PRs, where Cursor Bugbot reviews every PR with the severities in `.cursor/BUGBOT.md`. Rejected: a claude-review workflow (duplicates Bugbot, spends CI model calls) and reviewing open PRs (conflicting threads).
- Merges: a merge commit, head branches deleted; a plan phase lands as one PR with one commit per task, which keeps `git bisect` useful. Rejected: squash (loses task history) and rebase (changes the hashes review comments cite).
- Upgrades and releases: skill `upgrade` runs `scripts/upgrade.py` weekly on `chore/upgrades-<date>` and never touches `publish.yaml`; `scripts/pr_policy.py --bump` bumps by the commits since the last `v*` tag; skill `release` commits `chore: release vX.Y.Z` in the PR and tags after the merge. New packages, `publish.yaml` pins and uv bumps wait for the maintainer; a failed release fixes forward. Rejected: `release-please` and `python-semantic-release` (own the changelog or publish unreviewed).
- Brevity: rule `brevity` sets the budgets, `scripts/check_brevity.py` enforces them in prek and `make vault-check`, ruff enforces `PLR0915` and `C901`. A file at budget must not grow; old large functions are not split for it; vendored skills and agents are exempt. Facts repeated across README, docs, vault and rules drifted, an unchecked guideline drifts, compressed prose is hard to read.
